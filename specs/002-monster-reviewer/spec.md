# Feature Specification: 妖股审查员智能体 (Monster Reviewer Agent)

**Feature Branch**: `002-monster-reviewer`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "帮我看看文献里有没有人的研究对让我的系统看清妖股有帮助" → 结论：ElliottAgents（arXiv:2507.03435）的多智能体对话审查架构最值得借鉴，实现为"妖股审查员智能体"模块。

## Clarifications

### Session 2026-08-14

- Q: 妖股审查员应该接在每日自动流程的什么位置？ → A: 每日流水线集成。审查在 build_ranking 之后、generate_reports 之前运行，审查结果集成进每日报告，与现有自动化流程无缝衔接
- Q: 多智能体对话做到几轮？ → A: 两轮。审查员质疑 → 主报告回应 → 收敛结论，每标的 2 次 LLM 调用，成本可控
- Q: 审查哪些标的？ → A: 全部候选（含激进组合已持有与未持有的），输出完整风险图景
- Q: LLM API 不可用时审查环节怎么处理？ → A: 降级规则质疑。LLM 不可用时用规则生成质疑（如"10日涨幅超阈值""波动率超95分位"），流程不中断，每日报告照常输出审查章节，与现有 report_generator 的降级策略一致

## 背景 (Background)

### 立新能源案例引出问题

在立新能源（001258）案例验证中，教师指出"妖股"（短期连续涨停、高波动标的）缺乏机械规律，建议参考波浪理论。文献综述发现：

- **波浪理论对个股/妖股基本无效**（Ribeiro 明确 EWT 只适合大盘指数）
- **ElliottAgents（arXiv:2507.03435）** 提出"LLM 多智能体对话协同分析"架构，用自然语言对话让多个智能体互相质疑、确认、收敛——这是文献中对"看清妖股"最有帮助的思路

### 本项目的现状缺口

当前系统的 LLM 流水线是**单线程**的：
- 规则打分（KNN 概率、四因子评分）→ 单一 LLM 生成报告
- LLM 只负责"描述"事实，从不"质疑"信号
- 激进组合的入选标的（高涨幅、高波动）没有任何风险审查环节

### 目标

实现一个"妖股审查员智能体"（Monster Reviewer），专门负责对**高涨幅/高波动候选标的**提出质疑与风险审查，形成"审查员质疑 → 主报告回应 → 收敛结论"的多智能体对话，最终在每日报告中输出风险审查章节。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 审查触发（高涨幅/高波动标的筛选） (Priority: P1)

系统每日流程中，识别出需要被审查的"妖股候选"。

**Why this priority**: 没有触发识别，审查无从谈起。这是整个 feature 的入口。

**Independent Test**: 仅用规则代码（涨幅/波动率/换手阈值）即可独立测试，输出触发标的清单。

**Acceptance Scenarios**:

1. **Given** 每日排行数据（含涨幅、波动率、成交量），**When** 应用审查触发规则，**Then** 输出"妖股候选"清单：10 日涨幅 ≥30% 或 5 日波动率 ≥ 全市场 95 分位 或 涨停次数 ≥2 次/5日
2. **Given** 无候选标的（市场平稳），**When** 运行触发逻辑，**Then** 输出空清单并跳过 LLM 调用（节省 API）
3. **Given** 触发阈值配置（config 中可调），**When** 修改阈值，**Then** 触发清单随之变化且不报错

---

### User Story 2 - 审查员质疑（多智能体第一轮） (Priority: P1)

审查员智能体对候选标的提出质疑：涨幅过高风险、波动异常、量能背离、回调概率等。

**Why this priority**: 这是多智能体对话的核心——让 LLM 从"描述者"变成"质疑者"。

**Independent Test**: 用 mock LLM 响应测试 prompt 组装与解析逻辑，无需真实 API。

**Acceptance Scenarios**:

1. **Given** 候选标的数据（涨幅/波动率/量能/市场温度），**When** 组装审查员 system+user prompt 并调用 LLM，**Then** 解析输出为结构化质疑列表（质疑点 + 依据 + 严重度）
2. **Given** LLM 不可用（无 API key），**When** 运行审查，**Then** 降级为规则生成的质疑（如"10日涨幅超阈值""波动率超95分位"），不中断流程
3. **Given** LLM 输出不符合 JSON 格式，**Then** 容错解析（提取可用字段），不报错中断

---

### User Story 3 - 主报告回应（多智能体第二轮） (Priority: P1)

主报告智能体（或现有报告生成器）对审查员的质疑逐条回应，形成收敛。

**Why this priority**: 质疑必须有回应才有价值——这是"对话"而非"单方警告"。

**Independent Test**: 用 mock 审查结果测试回应 prompt 组装与解析。

**Acceptance Scenarios**:

1. **Given** 审查员的质疑列表 + 标的规则数据，**When** 组装回应 prompt 调用 LLM，**Then** 输出逐条回应（支持/反驳/数据不足）
2. **Given** 质疑严重度全部为"高"，**When** 生成收敛结论，**Then** 输出"建议降级关注"的倾向性结论（仅研究建议，非操作指令）

---

### User Story 4 - 每日报告集成（输出审查章节） (Priority: P2)

审查结果集成进每日报告/简报，用户能看到"审查对话"的可读摘要。

**Why this priority**: 审查的价值最终体现在用户可读的报告里。

**Independent Test**: 用已生成的审查结果（JSON）测试报告章节渲染。

**Acceptance Scenarios**:

1. **Given** 审查对话结果，**When** 生成报告章节，**Then** 输出"妖股风险审查"小节：候选清单 + 审查员质疑 + 主报告回应 + 收敛结论
2. **Given** 无候选标的，**When** 生成报告，**Then** 审查章节输出"今日无高波动标的"占位
3. **Given** 报告生成，**Then** 审查章节标注"研究信号仅供参考，不构成投资建议"（项目红线）

---

### User Story 5 - 独立 CLI 入口与测试 (Priority: P3)

提供独立命令行入口，便于手动运行与单元测试。

**Why this priority**: 便于调试、测试与门禁集成。

**Independent Test**: 命令行运行可手动验证。

**Acceptance Scenarios**:

1. **Given** 命令行执行，**When** 运行 `python -m src.llm.monster_reviewer --date 2026-08-14`，**Then** 输出审查报告 JSON 到 docs/data/
2. **Given** 单元测试，**Then** 覆盖：触发逻辑、prompt 组装、响应解析、降级路径、容错解析

---

### Edge Cases

- LLM API 不可用：降级为规则质疑，流程不中断
- LLM 输出非法 JSON：容错解析，提取可用字段
- 无候选标的：跳过 LLM 调用（省钱），报告输出占位
- 多个候选标的：逐个审查，但同一批共享一次系统 prompt（省调用次数）
- API 调用限额（每日 800 次）：审查员计入限额，超额时跳过 LLM 只出规则质疑

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 实现审查触发规则：10 日涨幅 ≥30% 或 5 日波动率 ≥ 全市场 95 分位 或 5 日内涨停 ≥2 次
- **FR-002**: 系统 MUST 实现审查员智能体：对候选标的输出结构化质疑（质疑点/依据/严重度）
- **FR-003**: 系统 MUST 实现主报告回应：对质疑逐条回应（支持/反驳/数据不足）
- **FR-004**: 系统 MUST 实现收敛结论：综合质疑与回应，输出"关注度建议"（正常/降级/警示）
- **FR-005**: 系统 MUST 实现降级路径：LLM 不可用时用规则生成质疑，流程不中断
- **FR-006**: 系统 MUST 实现容错解析：LLM 输出非法 JSON 时提取可用字段
- **FR-007**: 系统 MUST 在每日报告中输出"妖股风险审查"章节
- **FR-008**: 系统 MUST 计入 API 调用限额，超额时降级
- **FR-009**: 系统 MUST 遵守项目红线：审查结论为研究信号，非操作指令，不构成投资建议
- **FR-010**: 系统 MUST 提供独立 CLI 入口（--date 参数）

### Key Entities

- **妖股候选 (Monster Candidate)**: 触发规则筛选出的标的，属性：代码、名称、10日涨幅、5日波动率、涨停次数
- **质疑 (Challenge)**: 审查员输出，属性：质疑点、依据数据、严重度（高/中/低）
- **回应 (Response)**: 主报告对质疑的回应，属性：对应质疑、立场（支持/反驳/数据不足）、理由
- **收敛结论 (Verdict)**: 综合结果，属性：关注度建议（正常/降级/警示）、理由摘要
- **审查报告 (Review Report)**: 最终输出，属性：候选清单、质疑列表、回应列表、收敛结论

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 触发规则在历史数据上可复现（固定输入 → 固定候选清单）
- **SC-002**: 审查员输出结构化质疑，每条含质疑点/依据/严重度
- **SC-003**: 主报告回应覆盖全部质疑（一一对应）
- **SC-004**: 收敛结论输出明确的关注度建议（三选一）
- **SC-005**: LLM 不可用时降级路径输出规则质疑，流程完成不中断
- **SC-006**: 非法 JSON 时不崩溃，输出可用字段
- **SC-007**: 每日报告含"妖股风险审查"章节，无候选时输出占位
- **SC-008**: 全部功能经单元测试覆盖（预计 8-12 个测试）

## Assumptions

- 复用现有 LLM 基础设施（LLMClient.complete + FinGPTDeepSeekAdapter），不新增模型调用方式
- 审查员与主报告智能体都使用同一 DeepSeek API（不同 system prompt 区分角色）
- 审查在每日流程的 build_ranking 之后、generate_reports 之前运行（已澄清）
- 对话两轮：审查员质疑 → 主报告回应 → 收敛结论（已澄清）
- 审查全部候选标的（含激进组合持仓与未持仓）（已澄清）
- LLM 不可用时降级为规则质疑，流程不中断（已澄清）
- 触发阈值默认值可配置（config 新增一节），本次不接入模拟盘决策（只审查、不自动改仓位）
- 成本控制：同一批候选共享一次系统 prompt，每日新增调用 ≤ 5 次
