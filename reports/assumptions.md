# 建模假设记录

## 本次优化建议的目标与边界

- 目标：提高自选股在收盘后未来 3 至 5 个交易日的风险收益排序质量，重点减少高波动行情中的错误高排名和组合回撤。
- 决策变量：个股机会分、风险分、市场状态系数，以及由三者得到的最终排名或建议风险预算。
- 约束：沿用免费公开日线数据、GitHub Actions 收盘后运行、固定自选股池、可解释输出、零日常维护，不假设可获得稳定的分钟级或付费资金流数据。
- 可用数据：项目现有的约 5 年个股/ETF OHLCV、技术指标、行业或指数日线，以及可新增的主要宽基指数和全市场收盘截面数据。
- 主要评估指标：按交易日计算的未来 5 日 Rank IC、Top-K 相对基准收益、Top-K 最大回撤、命中率和换手率；不能只使用单次当前排名或样本内收益。
- 交付建议：先修复评分方向和缺失特征，再增加市场状态门控，最后进行走步回测和敏感性分析。

## 事实

- 当前风险子分对波动率、回撤和 ATR 使用了 `invert=True`，使较低风险值获得较高子分；但下游又把较高总分解释为更高风险并施加更强惩罚，方向存在冲突。
- 当前流程计算了 `industry_rs_20d`，但没有将其写入 `latest`；因此行业相对强度评分为空，KNN 中该特征也无法在最新值对象中被复用。
- 当前综合评分权重固定，不随市场趋势、波动、成交活跃度或风格切换而变化。
- 当前输出数据停留在 2026-07-17，不能代表 2026-07-31 的最新市场状态。

## 假设及影响

- 假设目标用户关注收盘后决策而非盘中交易。若实际目标是盘中择时，日线市场状态门控会明显滞后，需要分钟数据和不同的验证设计。
- 假设主要目标是改善风险调整后结果，而非追求单日最高收益。若用户只追求激进短线收益，风险门控会牺牲部分上涨阶段的收益上限。
- 假设自选池仍是主要分析范围。若目标改为全市场选股，需要处理幸存者偏差、历史成分股、ST/停牌/涨跌停和成交可实现性，工程量会显著增加。
- 假设行业分类和宽基指数历史数据可稳定获取。若免费接口持续不稳定，应优先做本地缓存和多源校验，否则状态判断可能退化或中断。
- 近期市场背景来自 2026-07-31 公开行情页面的收盘摘要，只用于提出候选方向，不等同于回测证据；结论必须由历史走步验证决定。
## 2026-08-06 代码接管与用户研究接入记录

- 事实：用户的个人研究资料位于 `本人研究成果/会计学大作业2.pdf`，本轮已抽取到 `reports/user_research_extract.txt` 供后续核对；代码中已有 `src/analysis/fundamental.py` 和 `src/analysis/fundamental_config.py`，其基本面评分框架使用资产质量、负债安全、盈利质量、现金健康四个维度，并把“技术面风险收益分”和“基本面分”按 50%/50% 融合为 `total_score`。
- 假设：当前版本先保留 Claude 已写入的用户研究框架，不在未完整人工复核 PDF 原文前继续调高其排序权重或宣称完全复现研究结论。影响：排行榜可继续生成，但基本面评分应视为“已接入框架、仍需复核阈值”的版本。
- 事实：本机当前东方财富接口经系统代理和直连都不稳定；普通股票可通过 AkShare 备用源恢复，ETF 已新增腾讯 qfqday K 线备用源，因此行情抓取已能做到 18/18 成功。
- 假设：腾讯 qfqday 数据作为 ETF 的免费备用源只用于 K 线和相似走势分析，不用于财务基本面。影响：ETF 没有三表基本面评分，`fundamental_score` 允许为 `null`。
- 事实：基本面三表抓取当前耗时不稳定，完整排行曾因此超时。本轮加入每只股票 8 秒的基本面分析超时保护，超时则跳过本次基本面分，并退化为技术/风险收益评分。影响：每日任务不会卡死，但当财务接口慢时 `total_score` 会等于 `risk_adjusted_score`。

## 2026-08-07 个人 PDF 研究规则核对

- 目标：将《本人研究成果/会计学大作业2.pdf》的研究逻辑转为实体企业的财务周期风险框架，用于解释存货、预付款、融资、现金回收和权益留存之间的关系；它不用于承诺个股收益或预测涨跌。
- 决策变量：行业周期状态（扩张、收缩、中性、未知）、存货加预付款占总资产比、资产负债率、短债占比、应收占营收比、经营现金流/净利润、未分配利润/归母权益。
- 事实：PDF 明确以佰维存储为案例，指出“存货+预付款接近总资产 60%”同时意味着上行周期中的供应链储备和反转后的减值、成本刚性与流动性风险；并强调应收回款、外部融资和未分配利润的交叉验证。
- 事实：原实现存在两个偏差：一是高存货在扩张期的说明文字为正面，实际评分仍然扣分；二是通用区间插值公式使应收、商誉、短债、现金流等多项风险扣分不能随指标恶化而正确增加。两项均已修正。
- 假设：35% 作为存货加预付款的提前观察线，60 个交易日内行业涨跌超过正负 3% 作为扩张或收缩判断，至少需要 21 个有效行业交易日；这些均是为了程序化落地而设的参数，PDF 并未给出跨行业统一数值。影响：参数必须通过后续的时间序列回测和敏感性分析验证，不能直接视为投资阈值。
- 假设：只有实际行业板块行情可用于周期判断，宽基指数不能代替行业供需；若没有足够真实行业数据，系统输出“周期未知”且不将高存货计为利好。影响：部分标的会少一项正面加分，但避免了缺失数据下的乐观推断。
- 假设：银行、保险、券商不适用本研究的“备货—预付—融资”实体企业模型，当前不输出该基本面分。影响：这些金融股仍保留技术面与风险收益分析；如需财务分析，应另建净息差、资本充足率、赔付率等行业模型。
- 限制：当前免费三表接口仍可能超时，导致基本面结果为 `null`，此时排序不会使用 PDF 框架。该降级行为已保留，以保证日常任务可完成；待财务数据源稳定或本地缓存完成后，才可评估该框架对排名的真实影响。

## 2026-08-07 FinGPT 方法论接入与项目重新定位

- 事实：项目新增研究材料 `本人研究成果/2306.06031v2.pdf`，论文题为“FinGPT: Open-Source Financial Large Language Models”，讨论数据中心化金融数据管线、金融文本任务、RAG、LoRA/QLoRA 和市场反馈标签。
- 事实：论文中的数据规模、模型配置和 Macro-F1 结果属于外部论文，不属于本项目结果；本项目只能将其作为方法论引用，并用中国 A 股数据独立验证。
- 目标：将项目定位为“金融分析 LLM（老年友好版）”，服务个人研究并作为 GitHub 开源项目，保留可解释基本面规则和行情风险分析。
- 决策变量：金融文本任务、个人研究基本面分、行情风险收益分、证据引用、置信等级和老年友好表达方式。
- 假设：先使用“规则引擎 + RAG + 开源模型”建立基线，再进行 LoRA/QLoRA 适配，最后评估市场反馈；不在没有数据和回测前宣称已经拥有有效金融大模型。
- 假设：基本面质量分主要适用于季度级研究，行情风险收益分主要适用于 3 至 5 个交易日观察；在走步回测完成前不强行合并为唯一总分。
- 限制：当前尚无中国 A 股金融文本训练集、独立测试集和市场驱动标签回测结果；这些缺口是后续研究任务，不得用 FinGPT 论文结果替代。

## 2026-08-08 FinGPT 风格流程接入 DeepSeek V4 Flash

- 目标：把现有规则评分、新闻情感、RAG 证据和市场反馈流程接到 DeepSeek API，生成可审计的中文金融研究报告；不训练模型、不自动交易。
- 决策变量：新闻采样数量、检索证据数量、是否启用 API、降级模式和报告叙述字段。技术、风险、行业、基本面及综合评分是程序计算的只读输入，不是模型可调整变量。
- 约束：推理模型固定为 `deepseek-v4-flash`；API Key 只来自环境变量或被 Git 忽略的本地文件；模型不得生成或修改评分、来源和日期；外部新闻一律按不可信材料处理；失败必须降级。
- 可用数据：`docs/data/analysis` 中的个股详情、公开新闻/公告、项目现有哈希 RAG 索引及市场反馈记录。缺失的基本面或新闻不得补造。
- 评估指标：本轮工程验收看 API 契约、固定模型名、批量调用次数、结构校验、引用审计、降级原因和离线测试；不把“API 调用成功”解释为预测有效。预测价值仍需时间切分回测、Rank IC、Top-K 超额收益和回撤验证。
- 交付物：DeepSeek 客户端、FinGPT 风格适配器、批量情感/RAG/报告链路、非敏感 `llm_metadata`、本地与 GitHub 配置说明、离线测试及一次最小真实 API 验证。
- 事实：DeepSeek 的 OpenAI 兼容 API 不能直接加载本地 FinGPT LoRA/QLoRA 权重；本轮接入的是 FinGPT 的方法流程，不宣称已经运行 FinGPT 权重模型。
- 假设：用户账户或兼容网关确实提供模型标识 `deepseek-v4-flash`。若服务端不识别该模型，核心调度会记录安全的失败类别且不保存模板报告，不会静默切换模型；手动独立路径仍可生成模板。该假设需要真实 API 冒烟调用验证。
- 限制：报告质量和情感标签尚未以独立 A 股标注集评估；当前哈希嵌入是可复现基线，不等同于高质量金融语义向量模型。

## 2026-08-08 短线观察提示与报告可核查展示

- 事实：页面顶部的短线观察状态只会输出“低风险观察”“谨慎观察”或“高风险”，并固定说明其仅用于学习和研究，不构成投资建议。
- 假设：规则以风险等级、历史相似样本的 5 日平均收益和样本置信度为最低可解释输入；仅在低风险、有效正收益且非低置信时标为“低风险观察”。影响：该状态便于快速浏览，但不能替代价格、流动性、公告、交易成本或个人风险承受能力判断。
- 限制：5 日统计收益来自历史相似样本，不是未来收益承诺；报告引用即使带有外部链接，也只能说明材料可追溯，不能证明模型结论或预测本身正确。

## 2026-08-08 核心排行榜调度 FinGPT 风格报告

- 事实：`src.build_ranking.main()` 在个股详情和 `ranking.json` 均已原子写入后，才调用报告阶段；报告只读取这些已落盘产物，不回写技术、风险、行业、基本面、综合评分或排行。
- 决策变量：是否启用报告阶段、每次处理的排行榜前 K 名、是否跳过同交易日已存在的 DeepSeek 深度报告，以及新闻抓取开关。约束：推理仍固定为 `deepseek-v4-flash`，没有可用密钥时不得发起新闻或 API 请求。
- 假设：每日只处理前 5 名足以在可接受的 API 成本和收盘后运行时间内提供主要观察对象。影响：未进入前 5 名的标的需要手动补跑，不能将“没有报告”解释为没有风险或没有信息。
- 假设：同一交易日已有符合元数据要求的 DeepSeek 报告可复用。影响：断点续跑不会重复收费；若规则输入、新闻或提示词发生变化，需显式关闭跳过开关后重新生成。
- 限制：报告生成或新闻抓取异常被隔离，不改变当日规则排行榜的退出码；核心调度只接受经验证的 `deepseek_api/deepseek-v4-flash` 结果，API 失败的模板不落盘也不写市场反馈。手动离线报告仍可使用模板，但其叙述质量、情感标签和市场反馈不能作为预测有效性的证据。
