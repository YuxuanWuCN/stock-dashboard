# 前后端共享数据合同

## 1. 基本规则

- 合同版本：`2.1`。
- 文件编码：UTF-8。
- 日期：`YYYY-MM-DD`。
- 时间：ISO 8601，必须包含 `+08:00`。
- 百分比字段直接使用百分数，例如 `2.35` 表示 `2.35%`。
- 分数字段范围 `0–100`。
- 无可靠结果必须使用 `null`，禁止用 `0`、`--` 或空字符串冒充。
- 后端输出英文键名；前端负责中文显示。
- 未经双方同步，不得删除、改名或改变字段类型。

### 3.1 可选 AI 研究报告

路径：`docs/data/llm/reports/{code}_{trade_date}.json`

该文件是个股详情的可选扩展；文件名中的 `code` 和 `trade_date` 必须与已加载的
`docs/data/analysis/{code}.json` 一致。报告文件不存在不是主分析失败，前端仅隐藏报告区域；
若报告文件存在，则必须满足下列 `2.1` 契约：

```json
{
  "schema_version": "2.1",
  "code": "600519",
  "name": "贵州茅台",
  "generated_at": "2026-08-08T18:00:00+08:00",
  "trade_date": "2026-08-08",
  "confidence": "medium",
  "research_report": {
    "title": "AI 研究报告",
    "summary": "必填的研究摘要。",
    "elder_friendly": "可选的通俗摘要。",
    "sections": [
      {
        "heading": "基本面评价",
        "content": "章节正文。",
        "citations": [
          {
            "source": "公开来源名称",
            "claim": "该引用支持的具体表述。",
            "date": "2026-08-08",
            "url": "https://example.com/source",
            "snippet": "可核查的原文片段。"
          }
        ]
      }
    ]
  },
  "citation_audit": {
    "total": 1,
    "evidence": 1,
    "inference": 0,
    "uncertain": 0
  },
  "llm_metadata": {
    "backend": "deepseek",
    "mode": "deepseek_api",
    "model": "deepseek-v4-flash",
    "pipeline": "fingpt_style_rag"
  },
  "disclaimer": "本研究基于公开历史数据，不构成投资建议。"
}
```

- `schema_version` 必须为主版本 `2`；当前生成版本为 `2.1`。
- `code`、`name`、`trade_date`、`disclaimer`、`research_report.summary` 均为必填字符串；
  `elder_friendly` 缺失时，前端回退展示 `summary`。
- `sections` 必须为数组，且每项的 `heading`、`content` 为字符串；`citations` 可省略，存在时必须为数组，
  每项至少包含非空 `source`。`claim`、`date`、`url`、`snippet` 为可选字符串。
- `citation_audit.total`、`evidence`、`inference`、`uncertain` 均为非负数字。只要 `total > 0`，
  前端就显示审计摘要；当 `evidence = 0` 时必须明确标注没有可核验证据。
- `llm_metadata` 必须包含非敏感的 `backend`、`mode`、`model`、`pipeline` 字符串；不得包含 API Key、
  Token、请求头或原始密钥文件内容。本部署使用固定模型 `deepseek-v4-flash`。
- 前端只为 `http` 或 `https` 引用地址创建外部链接，并使用 `target="_blank"` 与
  `rel="noopener noreferrer"`。
- 报告主版本不兼容、必填字段缺失或字段类型不符时，前端显示“研究报告数据版本不兼容或结构不完整。”，
  不得继续猜测解析或静默隐藏该报告。

## 4. 枚举

### 风险等级

| `level` | 分数 | 中文 |
|---|---:|---|
| `low` | 0–35 | 低风险 |
| `medium` | 36–65 | 中等风险 |
| `high` | 66–100 | 高风险 |

### 原因类型

- `positive`：加分原因。
- `warning`：需要观察。
- `negative`：扣分或风险原因。

### 置信等级

- `low`：样本不足或相似度较低。
- `medium`：样本达到最低要求。
- `high`：样本充分且相似度较高。

### 趋势

- `strong_uptrend`
- `uptrend`
- `range`
- `rebound`
- `downtrend`
- `insufficient`

## 5. 兼容性规则

- 前端遇到未知新增字段时忽略，不报错。
- 后端不得改变已有字段类型。
- 新增可选字段允许，但必须先提升次版本并更新本文档。
- 删除或改名字段属于破坏性变更，必须提升主版本。
- `schema_version` 不兼容时，前端显示“分析数据版本不兼容”，不得继续猜测解析。

## 6. 校验要求

后端必须提供 JSON Schema 或等价校验测试，至少验证：

- 必填字段存在。
- 分数在 `0–100`。
- 风险等级与风险分数一致。
- 百分比是数字或 `null`。
- 排名不重复。
- `succeeded + failed = total`。
- `trade_date` 不晚于北京时间当前日期。
- `stale=true` 时保留最后成功交易日信息。
- 可选研究报告存在时，验证其 `2.1` 必填字段、章节引用类型、引用审计非负性与非敏感元数据字段。
