# Code Quality Workflow

This project uses the three-level quality-gate method cloned and adapted from
`D:\数学建模作品`.

Before changing one focused unit of source code, record its intent:

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_quality.ps1 begin-unit `
  --name "short description" `
  --acceptance "observable acceptance criteria"
```

Run the matching level after the change:

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_quality.ps1 small
powershell -ExecutionPolicy Bypass -File tools/run_quality.ps1 medium
powershell -ExecutionPolicy Bypass -File tools/run_quality.ps1 heavy
```

- `small`: syntax, gate configuration, and focused unit tests.
- `medium`: small checks plus an offline integration pipeline test.
- `heavy`: medium checks plus reproducibility checks, full regression tests,
  and dependency consistency. A successful heavy gate closes the active unit.

Every invocation writes a JSON receipt below `.quality-state/reports/`. A failed
gate also creates a permanent issue entry in `bug合集/catalog.json`. These files
are generated by the gate and should not be edited by hand.
