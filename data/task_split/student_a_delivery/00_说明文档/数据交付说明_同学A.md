## 一、为什么不用仓库里那版 768 维文件

`scripts/crawl_and_extract_768d_factors.py` 在没有 LLM API Key 时会走离线兜底，
每支股票的摘要都是同一套模板文案（只替换股票名和板块名），导致哈希出的 768 维向量几乎同向：

| 指标 | 离线兜底 768d | 本次 CSMAR 日频面板 |
| :--- | :---: | :---: |
| 两两余弦相似度均值 | **0.794** | — |
| PC1 解释方差 | **40.7%** | — |
| 因子间平均 \|相关\| | — | **0.278**（11 个横截面日均值） |

相似度 0.794 意味着 100 支股票的特征几乎无法区分，下游 Fama-MacBeth 回归会严重秩亏。
**结论：那版文件不能直接用于回归。**

## 三、数据质量红线自检

1. **股票代码 6 位字符串** ✅
   全部 `ticker` 长度均为 6，前导零保留（如 `000021`、`000063`、`000089`）。
   读取时请使用 `dtype={"ticker": str}`。

2. **严禁跨股票污染** ✅
   缺失值填充用 `groupby("ticker").ffill()`，只在个股内部向前填充，且只用 `ffill` 不用 `bfill`，
   因此不会在个股首个交易日前凭空产生数值。

3. **停牌/退市处理** ✅
   停牌日不产生记录，由个股内部 `ffill` 顺延；退市股票在其最后交易日后不再有残留行。

## 五、复现方式

```bash
# 方式一：CSMAR 原生精确版（需额度，个人注册账号）
export CSMAR_USERNAME=你的账号
export CSMAR_PASSWORD=你的密码
export CSMAR_SDK_PATH=指向 csmarapi 目录   # 若未装进 site-packages
python scripts/build_csmar_daily_panel_factors.py --cohort student_A

# 方式二：新浪+腾讯快照重建版（无需 CSMAR，当日可用）
python scripts/build_panel_from_tencent.py student_A
# 试跑前 3 支：
python scripts/build_csmar_daily_panel_factors.py --cohort student_A --limit-codes 3
```

同学 B / C 把 `--cohort` 改成 `student_B` / `student_C` 即可复用（重建脚本同理）。

> 注意：CSMAR 单次查询上限 20 万条，**单表查询时间跨度不得超过 5 年**；
> 每日下载额度有限，重跑会自动复用 `data/_raw_cache/` 里的已取批次；
> 重建脚本带逐股断点缓存（`data/_raw_cache/tencent_parts/`）与安全阀
> （取数不全时拒绝落盘）。
